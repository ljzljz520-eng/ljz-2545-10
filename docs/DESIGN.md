# 站内设计说明 ·「湯けむり · 五感散步」

> 云麓温泉町（虚构地名）导览产品的原创设计。本文与 `docs/API.md`、`docs/DEPLOY.md` 配套。

## 1. 设计立场（四条不可逾越的规则）

1. **设施是一等公民，场馆是容器。** 维护、推荐、行程点全部挂到“设施/子设施”（泡池、浴区、餐饮楼层、客房、母婴室）。
   汤本馆的露天桧木池检修时，同馆的汤上食堂、以及全町任何住宿都**不会连坐消失**。
2. **推荐必须展开到用户真正要去的地方。** API 与页面的最小单元是设施（`facility_id`），不是场馆。
   “晨雾逐汤”给的是“内汤大池 → 川端足汤 → 汤上食堂”，而不是“汤本馆 → 足汤公园”。
3. **泉质是有来源的描述，不是功效承诺。** `spring_quality` 每行强制关联 `source_record`；
   入库 CHECK 禁止疗效断言词（治る/疗效/治愈/治疗/医疗功效）；所有出口固定附带免责声明。
4. **锁定是承诺，不是提示。** 用户手工锁定行程点后，开放时间或检修变化**永不移动、替换、删除**该点；
   系统只负责把冲突讲清楚（`locked_closed_conflict` / `locked_maintenance_conflict` / `hours_changed_after_lock`）。

## 2. 数据模型（PostgreSQL 为唯一事实源）

| 表 | 职责 |
|---|---|
| `source_record` / `link_check` | 来源、信任级别、失效/陈旧/待核状态与巡检留痕 |
| `place` / `place_alias` | 场馆/地点；`merged_into` 支持地点合并（旧点只读重定向） |
| `facility` | 设施树（`parent_id` 表示子泡池属于浴区）；亲子/住宿/餐饮标记 |
| `spring_quality` | 带来源的泉质观测（温度/pH/类型/观感），禁疗效词 |
| `opening_hours` | 周循环时窗，`crosses_midnight` 处理跨日营业；带生效区间与来源 |
| `maintenance` | 设施级维护，天然支持跨日（start/end 为绝对时间） |
| `walking_edge` | 有向实测步行边（上下坡方向耗时可不同），带来源/测量日期 |
| `segment_cache` | 全量/局部重算**唯一**的路段耗时来源；TTL + invalid 双新鲜度 |
| `itinerary` / `itinerary_item` | 行程版本号、设施级行程点、`manual_lock` 与锁定时窗快照 |
| `itinerary_recompute_log` | 每次 full/partial 的变更、冲突、缓存新鲜度审计 |
| `itinerary_edit` | 双设备乐观并发：基线版本、操作、是否冲突 |
| `offline_package` | 离线包版本与 `expires_at`，过期显式 expired |

为什么不用 PostGIS：坐标精度需求为街区级步行，haversine + 可插拔 OSRM 已足够；
保留经纬度双精度列与独立 `walking_edge`，部署零扩展依赖。需要时可平滑替换为 `geography`。

## 3. 时间窗算法（跨日/时区不允许有歧义）

- 所有内部计算都用**绝对时间**（`timestamptz` / JS `Date` UTC 毫秒），仅在解释层用 `Asia/Tokyo`。
- `openIntervals(rows, from, to)`：以“营业起始日本地日历日”为锚生成区间，
  `crosses_midnight` 时关门时刻 +24h；多扫前后各一天覆盖跨日窗。
- 地图筛选用 `openAtMoment`（此刻是否开着，未开则给“最近 HH:MM 开放”）；
  行程调度用 `earliestSlot`（在可达时刻之后找**单一开放窗内**、避开检修的最早可行段）。
- 维护与开放窗是交集约束：检修优先，跨日维护与跨日营业能正确判定。

## 4. 行程：完整重算 vs 按依赖局部修复

同一套 `rescheduleSuffix(items, startIndex)` 内核：

- **完整重算** `startIndex=0`：从用户起始时刻贪心铺排所有非锁定点。
- **局部修复** `startIndex=firstAffectedIndex(trigger)`：
  - 设施时窗/维护变化 → 从第一个用到该设施的点开始；
  - 地点坐标/步行边变化 → 从进入受影响边的第一个后续点开始；
  - 其**前缀的时间一个不动**（测试 `04` 明确断言）。
- 两者对同一路段都只经过 `segments.getSegment()`，所以同状态下结果签名完全一致（测试用 `facility@arrive` 签名比对）。
- 路段来源优先级：**实测边 → OSRM → haversine（4.5km/h）**；写缓存带 `expires_at`，
  数据侧改动调用 `invalidateForPlace` 双向失效；过期/失效缓存不命中并重算。
  每次重算把缓存新鲜度快照写入审计日志并返回页面。

## 5. 双设备并发

- 行程有单调 `version`；每次成功编辑 +1。
- 设备提交 `base_version`：落后即 **HTTP 409**，编辑落库为 `conflict=TRUE, applied=FALSE`，
  服务端绝不覆盖先到设备的修改；设备拉到新版本后可重试。
- 锁定/解锁同样是受控操作，避免两台设备互相抢锁。

## 6. 页面如何“说明过滤原因与待核信息”

- 筛选结果分两栏：**通过**与**被过滤**，每个被过滤点逐条列出原因码与中文解释
  （`merged` / `too_far` / `no_facility_match` / `unavailable_at_time` / `inactive`）。
- 地图上被过滤点用灰色虚线针标记，可点击看原因；合并点红色边框。
- **待核信息**用「核」印戳样式与正式数据区分（如亲子馆开放时间仅 SNS 单一来源、夜鸣屋台季节性营业）。
- 行程冲突用红印签卡片说明，且同时展示“锁定时时表 / 当前时表”，把决定权交还给用户。

## 7. 原创主题（文案与动线均原创）

1. **朝靄の湯めぐり（晨雾逐汤）** — 开汤第一缕蒸汽：内汤暖身、溪边足汤醒神、食堂收尾。
2. **泡のち親子（泡泡亲子半日）** — 亲子戏水厅 → 同馆母婴室 → 家庭友好食堂，全程 10 分钟步行圈。
3. **夜蒸し屋台街（夜蒸小吃线）** — 泡到晚场，再去跨夜营业的屋台（22:00–次日 01:00）。

## 8. 视觉系统

- 取色来自温泉现场：**桧木绿 #5b7a56**、**藏青蓝 #243447**、**朱印红 #c0392b**、米纸底 #f5f1e6。
- 和纸卡片 + 粗界朱红分隔；标题用明朝体，正文用黑/黑体；地图水滴针按业态着色。
- 无第三方 UI 框架、无构建步骤；Leaflet 已 vendored 到 `public/vendor`，底图可由离线包替换。
